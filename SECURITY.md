# Security Policy & Architecture Notes (`SECURITY.md`)

This document describes the security controls implemented in **Bajrang AI** (`bajrang_core.py`, `windows.py`, and `fedora.py`), as well as the known limitations and operational boundaries of the system.

## 1. Credential Storage (`SecurityVault`)
- **No Plaintext API Keys in `settings.json`**: `ConfigManager` strips all secret fields (`byo_api_key`, `api_key`, `cloud_api_key`, `secret_key`) before writing `settings.json`.
- **Storage Hierarchy**:
  1. **OS Keyring (`keyring`)**: Preferred backend when the Python `keyring` package and a system keychain (Windows Credential Locker, macOS Keychain, or Freedesktop Secret Service) are available.
  2. **Windows DPAPI**: Uses `System.Security.Cryptography.ProtectedData` (`CurrentUser` scope) on Windows when `keyring` is absent.
  3. **Linux `secret-tool`**: Uses `libsecret` when an active `DBUS_SESSION_BUS_ADDRESS` is present.
  4. **Headless Local Fallback (`.sec` with `0600` permissions)**: On headless systems without an OS keyring or D-Bus daemon, secrets are obfuscated with a key stream derived via PBKDF2-HMAC-SHA256 from local host/user identifiers and saved with `0600` (`stat.S_IRUSR | stat.S_IWUSR`) file permissions. **Limitation**: This headless fallback protects against casual inspection and accidental config sharing, but does not protect against a local attacker running as the same OS user.
- **Redaction**: `redact_sensitive_text()` scrubs recognizable API key prefixes (`AIza...`, `gsk_...`, `sk-...`), `Bearer` tokens, and password assignments before writing chat messages or memories to SQLite (`history.db`).

## 2. Command Execution & Desktop Automation (`SafetyGuard` & `ShellRunner`)
- **Fail-Closed Allowlist (`strict_allowlist=True` by default)**:
  - `ShellRunner` executes commands exclusively with `subprocess.Popen(argv, shell=False)`.
  - `SafetyGuard` rejects any command containing shell metacharacters (`;`, `|`, `&`, `` ` ``, `$`, `>`, `<`, newlines) and only allows executables listed in `SafetyGuard.ALLOWED_BINARIES`.
  - Privilege escalation prefixes (`sudo`, `su`, `pkexec`, `doas`, `runas`) and destructive disk/filesystem commands are blocked unconditionally.
- **Path Boundary Validation**:
  - `ToolSchemaValidator.validate_safe_user_path()` resolves symlinks and environment variables and restricts file operations (`inspect_directory`, `organize_directory`) to directories inside the current user's home directory (`Path.home()`) or temporary directory (`tempfile.gettempdir()`).
- **Explicit Confirmation for File Changes**:
  - `AutonomousTaskPlanner` separates non-destructive directory inspection (`create_organization_plan`) from file movement and duplicate deletion (`execute_approved_plan(plan_id, user_confirmed=True)`). It refuses to move or delete files unless `user_confirmed=True` is explicitly passed.
- **Emergency Kill-Switch (`KillSwitchManager`)**:
  - Tracks spawned child processes and terminates them via `SIGTERM` → `SIGKILL` (after `grace_ms`) on POSIX or `taskkill /F /T /PID` on Windows when triggered (`Ctrl+Escape`).

## 3. Licensing Verification (`LicenseManager` & `AsymmetricLicenseVerifier`)
- **Asymmetric Server-Signed Certificates (`BAJRANG-V6-...`)**:
  - Verified using RSA public-key modular exponentiation (`E = 65537`, `PUBLIC_MODULUS_HEX`). The desktop client does not contain the private signing key (`D`), which must reside on an external verification server (`razorpay_server.py`).
- **Demo Tokens (`BAJRANG-PRO-...` / `BAJRANG-DEMO-...`)**:
  - Offline tokens generated by `LicenseManager.generate_key()` use a non-cryptographic checksum (`DEMO-NONCRYPTOGRAPHIC-CHECKSUM`) and are explicitly marked `[DEMO_ONLY_UNVERIFIED]` in status outputs. They exist solely for local UI testing and self-tests and do not provide commercial DRM protection.
