    SECURITY & ARCHITECTURE FAQ

    Frequently Asked Questions

    How does the safety guard prevent shell escalation?

    Sudharshan AI runs fail-closed with a 4-tier permission model (Read-Only, Safe-Write, Elevated-Confirm, Hard-Blocked), excludes arbitrary shell_exec from AI tool dispatch, sanitizes commands against fork bombs and pipe-to-shell patterns, and terminates all child processes immediately on the panic kill-switch.

    Which packages run on Fedora Workstation?

    Fedora Workstation 39–43 with GNOME Shell on Wayland, GTK4 / Libadwaita, PipeWire for local audio capture, Ollama for local Qwen 3.5 weights, and optional QEMU/Podman for building and booting Sudharshan OS ISOs.

    Where does the vault store encryption keys and chat logs?

    Chat logs and RAG indexes stay in local SQLite WAL databases on your machine. Optional BYO API keys are isolated in OS hardware vaults (GNOME Keyring / libsecret on Fedora, Windows Credential Manager / DPAPI on Windows) and never leave your device unless you explicitly toggle Cloud Burst.

    How does the server sign Pro license keys?

    Pro certificates use 2048-bit RSA asymmetric signatures verified completely offline in bajrang_core.py with zero client-side key minting and zero telemetry.
