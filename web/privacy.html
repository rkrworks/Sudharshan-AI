Privacy Policy

Last updated: November 2026 · Sudharshan AI (Alpha v0.9)

1. Local-First Architecture

Sudharshan AI (Alpha v0.9) is engineered from first principles to prioritize device isolation. Chat sessions, user preferences, long-term memory, and task execution logs are persisted exclusively in a local SQLite3 database on your host operating system using Write-Ahead Logging (WAL) mode.

2. Zero Remote Telemetry & Offline Default

The desktop software transmits no tracking metrics, usage analytics, behavioral telemetry, or session recordings to central servers. When you run local models via Ollama (Llama 3.2, Llama 3.1, Mistral, Gemma 2, etc.), all inference execution remains completely local on your CPU/GPU hardware.

3. Hardware Credential Vaulting

Optional third-party cloud API keys (Google Gemini, OpenAI, Groq, OpenRouter) are sealed inside native operating system credential vaults (Windows Credential Manager on Windows 11; Secret Service API / GNOME Keyring on Fedora Linux). Plaintext secrets are never stored in log files or leaked in URL query parameters.

4. Screen & Audio Processing

Screen grabs and microphone audio streams are processed in-memory for explicitly requested user turns and discarded immediately upon completion. The multilingual voice engine (supporting Telugu, Hindi, Tamil, Kannada, Spanish, French, etc.) uses local DSP Goertzel keyword spotting and in-memory speech synthesis without continuous background surveillance.

5. Non-Destructive File Operations

All automated file operations (organization, deduplication, renaming, quarantine) follow strict collision-avoidance naming (e.g., filename_1.ext) and stage affected files into .bajrang_trash/ directories with full multi-point undo capability before any action is executed.
